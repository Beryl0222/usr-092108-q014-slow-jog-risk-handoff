# 超慢跑风险接力

社区健康中心超慢跑活动的风险接力服务。每场活动前，服务把每位参与者落入三种**可解释**状态之一：

| 状态 | 含义 |
| --- | --- |
| `CONTINUE` | 可以按当前计划继续 |
| `REDUCE_OBSERVE` | 先降低负荷观察 |
| `PAUSE_HANDOFF` | 暂停并交给专业人员 |

只按配速或年龄分组做不到这一点：状态由本人目标、基础活动水平、自报风险、医生参与范围、动作评估、近期负荷与主观感受、异常信号、场地温湿度共同决定，并且每次判定都给出依据（`reasons`），参与者看得懂，医生可追溯。

## 目录结构

- `contracts/domain.schema.json`：领域事件信封契约（必填字段、事件类型、聚合类型），是校验的单一事实源。
- `src/domain.js` / `src/domain.ts`：领域常量与类型（状态、建议动作、信号、来源）。
- `src/event-store.js`：追加式事件存储；事件标识、发生时间、版本不原地改写，重传按 `event_id` 去重。
- `src/rules.js`：经审核的规则引擎。
- `src/service.js`：`RiskHandoffService` 主服务（命令、评估、角色视图）。
- `src/validator.js`：按契约校验事件信封。
- `data/sample.json`：可用于联调的中文样例记录。
- `tests/`：契约、校验器与服务行为测试。

## 保存的领域资料

参与者档案（本人目标、基础活动水平、自报风险）、医生给出的参与范围、动作评估、分组计划（版本化）、场次与场地温湿度、每次负荷与主观感受（RPE）、异常信号、暂停决定、复评安排，全部以追加事件落账（见 `svc.events()`），业务更正产生后继记录，既往轨迹不回写。

## 关键行为约定

- **可解释状态**：`assess(participant_id, session_id)` 返回状态与依据列表。暂停未解除、未处置红旗信号、审核规则建议停止 → 暂停交接；审核规则提示、异常设备值未确认、RPE 偏高、达到医生上限、场地高温高湿、复评后降量恢复的首场 → 降量观察；否则继续。
- **审核规则**：`registerRule` 只接受 `CONSULT / REDUCE / STOP` 三种建议动作，必须携带审核人及审核时间；条件只能引用白名单事实字段。规则不诊断疾病，也不修改治疗。
- **异常设备值**：设备读数超出合理区间（心率 30–220、时长 1–300 分钟、RPE 0–10）即进入 `PENDING_CONFIRMATION`，确认前不计入负荷历史、不允许加量（`approvePlan` 提量会被拒绝）；人工确认或更正（产生后继记录）后才生效。
- **计划版本**：`approvePlan` 生成新版本，自下一场生效；每条负荷记录绑定当时的计划版本，既往记录不回写。
- **只累计一次**：网络重传按 `submission_id` 幂等；缺席按场次+人去重；同人同日跨点参加只计首次到场。
- **多源矛盾**：同场同人多来源记录数值差异超阈值时互相标注 `conflict`；可信历史按 人工签到 > 穿戴设备 > 本人补录 的优先级每场采信一条。
- **红旗信号**：胸痛、眩晕、急性损伤出现时，人工处置抢占普通课程（教练视图中该参与者标记 `preempted`），记录交接（`clinical_handoff`）并作出暂停决定；复评结论为恢复时才解除暂停。
- **角色视图**：`coachView` 只给带课必要信息（分组、目标负荷、动作注意、状态、是否被抢占）；`participantView` 公开状态依据；`doctorView` 给出去重、冲突标注、异常未确认不计入的可信负荷历史；`operatorStats` 只输出去标识聚合结果。
